# rsi-common Invariants

## Type contracts

- `Session.working_dir` is `PathBuf` (not `Option`) — every constructor MUST supply an absolute path; daemon `launch.rs:41-49` falls back to `current_dir()` then `/tmp`. Empty / non-canonical paths are rejected at the RPC boundary, not here. (`crates/rsi-common/src/types.rs:122`)
- `Session.id`, `created_at`, `updated_at`, `query`, `status` are non-optional load-bearing identity fields. `claude_session_id: Option<String>` may be `None` until the provider emits the first session-init event. (`crates/rsi-common/src/types.rs:75-99`)
- Sandbox columns travel as a 4-tuple. The on-disk contract is: `sandbox_kind == Some(_)` ⇒ `sandbox_root == Some(_)` AND `sandbox_cleanup_state == Some(_)`; `sandbox_kind == Some(SandboxKind::GitWorktree)` ⇒ `sandbox_branch == Some(_)`. All four `None` for non-sandboxed sessions. Daemon `launch.rs:466-471` is the only canonical writer. (`crates/rsi-common/src/types.rs:286-300`)
- `Session.rotation_depth: u32` — depth in rotation chain, 0 = original. Auto-rotation must abort once child depth reaches 4 (see lifecycle invariants). (`crates/rsi-common/src/types.rs:86-89`)
- `Session.continued_from: Option<Uuid>` and `Session.parent_id: Option<Uuid>` are independent: `continued_from` tracks rotation chain ancestry (linked list), `parent_id` is the organizational tree (Group/Epic). They MUST NOT be conflated. (`crates/rsi-common/src/types.rs:135-143`)
- `Session.session_kind` is partitioned by `is_leaf_kind()` and `is_container_kind()`. Spawn callers MUST gate on `is_leaf_kind` (daemon enforces at `launch.rs:32`). Hierarchical placement MUST consult `legal_children(parent)`. (`crates/rsi-common/src/types.rs:390-437`)
- Outcome / telemetry fields (`rating`, `harness_version_hash`, `test_passed`, `clippy_passed`, `turn_count`, `retry_count`, `approval_wait_ms`) are nullable: `None` = unmeasured, `Some(false)`/`Some(0)` = measured. Downstream MUST pattern-match `Option`, never coerce `None` to zero. (`crates/rsi-common/src/types.rs:222-284`)
- `ConversationEvent.id: i64` — `0` is the pre-persistence sentinel. `content: String` (never `Option`) — empty string when no content. `sequence: i32` is per-session monotonic and must be assigned by the daemon, never by the TUI. (`crates/rsi-common/src/types.rs:459-475`)
- `ContextUsageConfidence::Stale` is **runtime-only** — it is never persisted to the DB and resets to `Missing` on rehydrate. Persistence layers must transform `Stale` → `Missing` before write. (`crates/rsi-common/src/types.rs:506-514`)
- `EntityCard::MAX_FACTS = 40`; consumers SHOULD reject card writes that exceed this. (`crates/rsi-common/src/types.rs:880-883`)
- `RpcRequest.params` carries `#[serde(default)] params: Value` defaulting to `Value::Null`. Handlers MUST handle `Null` explicitly (typically via `serde_json::from_value` on a typed params struct), never `unwrap_or` it. (`crates/rsi-common/src/rpc.rs:13-19`)
- `BusEvent { event_type: String, ... }` is a struct, not an enum — daemon defines `DaemonEvent` and converts via `From<DaemonEvent> for BusEvent`. The `event_type` strings are part of the wire contract; renaming a variant breaks subscribers. (`crates/rsi-common/src/rpc.rs:413-419`, `crates/rsid/src/bus.rs:186-200`)
- `HandoffStatus` enum lowercases via `#[serde(rename_all = "lowercase")]`. Lenient frontmatter accepts free-string status (legacy values like `in-progress`, `wip`); strict variant rejects unknowns via `#[serde(deny_unknown_fields)]`. (`crates/rsi-common/src/handoff_schema/frontmatter.rs:67-92`)
- `ResearchDoc` and every nested struct carry `#[serde(deny_unknown_fields)]`. v2 documents (with new keys) MUST be rejected by a v1 validator; the consumer falls back to markdown. (`crates/rsi-common/src/research_schema/schema.rs:11-50`)
- `FileRef.lines: [u32; 2]` — exactly two elements. Serde rejects arrays of any other length. (`crates/rsi-common/src/research_schema/schema.rs:36-39`)
- `Stage` (agent contract) maps three uppercase strings (`RESEARCH`, `PLAN`, `IMPLEMENTATION`); other captures land in `ContractError::UnknownStage`. The em-dash (U+2014) in `PIPELINE HANDOFF —` is mandatory and rejects hyphen-minus. (`crates/rsi-common/src/agent_contract.rs:83-138`)

## Lifecycle invariants

- `SessionStatus` transitions: `Starting → Running → {Completed | Failed | Interrupted | WaitingApproval}`; `WaitingApproval` resumes back to `Running` on answer. `Archived` and `Deleted` are terminal sinks reachable from any other state. `is_terminal()` returns true for `Completed | Failed | Interrupted | Archived` (note: `Deleted` is NOT in the terminal predicate). (`crates/rsi-common/src/types.rs:440-456`)
- `WorkflowStage` is **strictly forward-only**: `Research → ResearchComplete → Planning → PlanComplete → Implementing → ImplementComplete → Complete`. No regression edges. (`crates/rsi-common/src/types.rs:587-604`)
- `WorkflowExecutionStatus` is one of `Accepted | Running | Succeeded | Failed | Interrupted`. `Accepted → Running → {Succeeded | Failed | Interrupted}` is the implied DAG; `WorkflowNodeExecutionState` covers nodes with the reduced set `Running | Succeeded | Failed`. (`crates/rsi-common/src/types.rs:734-751`)
- `SandboxCleanupState`: `Live → Purged` on successful destroy; `Live → Failed` on partial destroy. Orphan sweep retries `Failed`. Idempotent: destroy on an already-`Purged` allocation is a no-op. (`crates/rsi-common/src/types.rs:317-327`)
- `parse_pipeline_handoff` requires the `PIPELINE HANDOFF — <STAGE>:` marker in the **first 200 bytes** of the reply (multiline-anchored). Any prose / narration before the marker is a contract violation. (`crates/rsi-common/src/agent_contract.rs:136-167`)
- `validate_handoff(content, mode)` validates frontmatter THEN body sections; collects all errors (no short-circuit) so the user sees the full rejection list per call. (`crates/rsi-common/src/handoff_schema/rules.rs:194-200`)
- `probe_or_fallback`: 4-step decision tree (no JSON file → fallback; read fail → fallback; validation fail → fallback; otherwise `JsonValid`). Silent on the fallback path — never panics, never logs the reason. (`crates/rsi-common/src/research_schema/mod.rs:79-106`)
- `HANDOFF_SCHEMA_VERSION = 1` and `RESEARCH_SCHEMA_VERSION = 1`: bumping requires a code change. v2-only fields on a v1 binary land as `ValidationError` and consumers must fall back to markdown. (`crates/rsi-common/src/handoff_schema/rules.rs:33`, `crates/rsi-common/src/research_schema/rules.rs`)
- `env_with_legacy()` treats empty environment values as not-present, so a stray `RSI_X=` does not shadow `MOTHERSHIP_X=foo`. (`crates/rsi-common/src/identity.rs:69-83`)

## Cross-crate contracts

- The daemon owns canonical `Session` row writes; `rsi` (TUI) treats `Session` as a read-only DTO and may only mutate it via RPC. Direct mutation in the TUI's local copy is allowed but never persisted. (Daemon `crates/rsid/src/session/launch.rs:466-473` is the canonical writer.)
- `is_leaf_kind` and `legal_children` are imported by `rsid` (`session/launch.rs:32`, `session/hierarchy.rs`) and by `rsi` overlay flow. Both crates MUST agree on the partition; redefining either function inside one crate is forbidden. (`crates/rsi-common/src/types.rs:388-437`)
- `RpcRequest`/`RpcResponse` JSON shape is the daemon ↔ TUI wire contract. The `id: Option<Value>` is free-form (number or string) — both crates serialize/deserialize via the same struct definitions in `rsi-common::rpc`. (`crates/rsi-common/src/rpc.rs:13-69`)
- `DaemonCapabilities` is the feature-negotiation handshake: each `bool` field with `#[serde(default)]` lets a newer TUI talk to an older daemon and detect missing capabilities (`false` from default). The TUI MUST treat absent fields as `false`, never assume support. (`crates/rsi-common/src/rpc.rs:246-327`)
- `SessionProvider` discriminator strings are persisted as text in SQLite and must round-trip stably across crate revisions. Adding a new variant requires migration planning (`crates/rsid/src/store/row_mappers.rs`). (`crates/rsi-common/src/types.rs:341-357`)
- `BusEvent.event_type` strings (`"session_status_changed"`, `"sandbox_orphan_cleaned"`, etc.) are wire identifiers; renaming a `DaemonEvent` variant requires updating the `From` impl and any TUI subscriber switch arm. (`crates/rsid/src/bus.rs:186-200`)
- `ENV_SOCKET = "RSI_SOCKET"` plus legacy fallbacks `MOTHERSHIP_SOCKET` and `FLYWHEEL_SOCKET` are checked in order by both daemon and TUI via `default_socket_path()`. Both crates MUST use this helper, never re-implement env-var lookup. (`crates/rsi-common/src/identity.rs:55-83`)
- `agent_contract::Stage` and `handoff_schema::HandoffStatus` are independent grammars (inline reply vs. on-disk doc). The two share lenient/strict philosophy but their string vocabularies do not overlap (`RESEARCH/PLAN/IMPLEMENTATION` vs. `complete/paused/blocked`). (`crates/rsi-common/src/agent_contract.rs:11-18`)

## Performance invariants

- `Session` field layout is intentionally cache-aligned (line 1 = identity + hot render fields; line 2-3 = display strings; line 4 = secondary identity; line 5+ = cold analytics). Reordering fields can degrade list-render perf at 1000+ sessions. (`crates/rsi-common/src/types.rs:75-300`)
- `LATEST_SCHEMA_VERSION` is a daemon-side constant (`crates/rsid/src/store/mod.rs:40`), not in `rsi-common`. Any common-side type extension that requires a column MUST be paired with a daemon migration bump, or the TUI will deserialize `None` from missing columns rather than failing fast.
- `validate_first_line` and `validate_worker_report_first_line` only scan the first 200 bytes (`MARKER_SCAN_WINDOW`). The check is constant-time regardless of reply length. (`crates/rsi-common/src/agent_contract.rs:150,196-208`)
- `is_leaf_kind` and `is_container_kind` are `#[inline]` — they appear on every spawn-time decision and every list-render filter. Inlining is load-bearing for steady-state CPU. (`crates/rsi-common/src/types.rs:388-407`)
- `#[serde(default)]` on every nullable `Session` field means a v1 daemon can deserialize a v0 row (or vice versa) without a panic. Forward-compat depends on every new field being `Option<...>` with `#[serde(default)]`. (`crates/rsi-common/src/types.rs:80-300`)
- `prompt_compile::CompileResult` is sized to fit inside one `BusEvent::CompilePromptCompleted` payload; ChatGPT-sized chunked streaming uses `CompilePromptChunk` deltas instead. Avoid stuffing large payloads through the synchronous request/response path. (`crates/rsi-common/src/prompt_compile.rs`, `crates/rsid/src/bus.rs:161-175`)
