# rsi Invariants

## Type contracts

- `PaneId(u64)` is a newtype wrapper; `DETAIL_LIST_SENTINEL = PaneId(u64::MAX)` is reserved for the tab-stored session-list state and MUST NOT be assigned to any layout-tree leaf. (`crates/rsi/src/types.rs:11-12,521`)
- `SplitNode::Leaf { pane, id }` and `SplitNode::Split { id, .. }` — every node carries a unique `id`. The `next_pane_id` counter on `App` MUST be monotonically increasing; reusing an ID for a recreated leaf will corrupt the focus state. (`crates/rsi/src/types.rs:425-435`)
- `Tab.session_list_state` is the persistent fallback `SessionList` pane used when the layout tree contains no `SessionList` leaf (single-pane detail mode). It is updated when entering a session from a `SessionList` pane and replayed on tab restoration. (`crates/rsi/src/types.rs:531-577`)
- `Pane::SessionList` carries four selection indices (`selected_index`, `taskrabbit_selected_index`, `archive_selected_index`, `jobs_selected_index`) — one per `SessionListZone` — plus `active_zone`. The active zone determines which index drives selection rendering. Each index MUST stay in `[0, sessions_in_zone.len())` after every list mutation. (`crates/rsi/src/types.rs:29-44`)
- `OverlayState` (line 1878) is mutually exclusive with normal navigation — when an overlay is active, all keypresses route to the overlay handler in `overlay/`. The non-`None` overlay variant gates input dispatch in `action_handler/mod.rs`. (`crates/rsi/src/types.rs:1878`)
- `PersistedState` is the restart-survival state (tabs, project filter, model, sort, jumplist, settings); `DevState` is hot-reload-only (scroll positions, fold states, drafts). Confusing the two means user prefs vanish on restart or scroll positions persist across daemon restarts. (`crates/rsi/src/state.rs:37-180`)
- `ModelDropdownState.open` and `ModelDropdownState.models` invariant: when `open == true`, `models` MUST be non-empty (otherwise the user sees a blank dropdown). Caller supplies models from `DiscoverModels` RPC. (`crates/rsi/src/types.rs:56-108`)
- `PollController.connected` reflects daemon socket state at the last `request()` call. Capability flags (`batch_fetch_supported`, `push_supported`, `memory_search_supported`, `sandbox_supported`) default to `false` for a newer TUI talking to an older daemon — except `batch_fetch_supported`, which defaults to `true` for legacy fallback. (`crates/rsi/src/poll_controller.rs:25-51`)
- `PollPhase` cycles `Connect → ListSessions → ListProjects → ListLabels → FetchConversations { ids, index } → ...` — each variant is one RPC round-trip; render frames fire between phases so the event loop never blocks for the full poll. (`crates/rsi/src/poll_controller.rs:7-18`)
- `BorderColorOverrides([Option<[u8;3]>; 7])` — exactly 7 slots, indexed `[assistant, user, tool_unselected, tool_selected, normal_cursor_bg, insert_cursor_bg, visual_selection_bg]`. Reordering slots silently corrupts user color prefs. (`crates/rsi/src/state.rs:18-34`)
- `DaemonClient.pending_response: bool` — when `true`, a fire-and-forget request is in flight and the next `request()` MUST drain it via `drain_pending()` before issuing its own request. Failing to drain leaks a response into the next call's deserializer. (`crates/rsi/src/client.rs:36-50,142-169`)

## Lifecycle invariants

- TUI keypress pipeline order: crossterm `Event` → `modalkit` `VimMachine` → `LcAction` → `dispatch_lc_action()` (`action_handler/mod.rs`) → submodule (navigation/session/overlay/window). Every new action MUST be added in **this exact order** through all four sites. (CLAUDE.md, `crates/rsi/src/keybindings.rs`, `crates/rsi/src/modalkit_types.rs`, `crates/rsi/src/action_handler/mod.rs`)
- Adding a TUI keybinding requires updating `docs/keybindings.md` with `make manual`. Failure to do so is a documented contract violation per CLAUDE.md, enforced by the `manual::tests` drift tests.
- Overlay activation is mutually exclusive: opening one overlay MUST close the previous (or place it on a stack the caller manages). The current code uses single-overlay state — multi-overlay stacking is not supported. (`crates/rsi/src/types.rs:1878`)
- `DaemonClient::launch_session` is fire-and-forget — the response is drained on the next call, errors are logged, not propagated to the caller. The TUI discovers the new session via the next `ListSessions` poll, not the launch reply. (`crates/rsi/src/client.rs:118-140,190-200`)
- `PersistedState::save` errors are silently ignored (best-effort); `PersistedState::load` returns `Self::default()` on read or parse failure. State corruption is recoverable by deleting `~/.rsi/state.json`. (`crates/rsi/src/state.rs:153-179`)
- `DevState` auto-clears on load — it survives only across hot-reloads of the same TUI process, never across full restarts. (`crates/rsi/src/state.rs`, see CLAUDE.md "State Persistence")
- `Pane::SessionDetail { session_id }` requires the referenced session to exist in `App.sessions` at render time; missing sessions render an empty pane (no panic). The TUI relies on the next poll to populate it. (`crates/rsi/src/types.rs:46`)

## Cross-crate contracts

- `DaemonClient` socket path resolved via `rsi_common::identity::default_socket_path()` — TUI MUST NOT re-implement env-var lookup. Connect failure surfaces as `ClientError::NotConnected` and the poll controller flips `connected = false`. (`crates/rsi/src/client.rs:54-56,59-63`)
- The TUI binary routes session mutations through `DaemonClient::*` JSON-RPC methods. This is an architectural choice — the TUI is the daemon's RPC client by design — not a project-wide prohibition on raw SQL. (Raw SQL is allowed from other tooling; see CLAUDE.md "Database Rules" for the two hard rules: no schema changes without a migration, no hard deletes without explicit user consent.)
- `SessionStatus` variants from the daemon are matched **exactly** in TUI render paths (`Starting`, `Running`, `WaitingApproval`, `Completed`, `Failed`, `Interrupted`, `Archived`, `Deleted`). Renaming a daemon-side variant breaks status-bar rendering until the TUI is rebuilt. (`crates/rsi-common/src/types.rs:440-449`, consumer `crates/rsi/src/ui/`)
- The TUI consumes `BusEvent.event_type` strings — `"session_status_changed"`, `"conversation_event"`, `"session_stalled"`, etc. — from `notification_stream.rs`. The string vocabulary is owned by the daemon's `From<DaemonEvent>` impl. (`crates/rsi/src/notification_stream.rs`, `crates/rsid/src/bus.rs:186-310`)
- `DaemonCapabilities.sandbox` is read on connect and stored as `PollController.sandbox_supported`. The `s` toggle in the new-session prompt overlay AND the sandbox indicator in session rows MUST gate on this flag. Default-false guards older daemons. (`crates/rsi/src/poll_controller.rs:36-38`, `crates/rsi-common/src/rpc.rs:298-302`)
- `Session.handoff_filepath: Option<String>` is set by the daemon when a session writes a handoff via the Write tool intercept. The TUI uses this to render the handoff button — it does NOT validate the file exists, since the daemon owns that signal. (`crates/rsi-common/src/types.rs:144-147`)
- `is_leaf_kind` and `legal_children` from `rsi-common` are the **only** authority on which session kinds are spawnable / containerable. The new-session overlay form MUST consult these, never re-implement. (`crates/rsi-common/src/types.rs:388-437`)

## Performance invariants

- `App::tick()` and the poll loop are interleaved by phases (`PollPhase`) so render frames fire between RPCs — no single phase may block more than a few ms. Long-running RPCs (e.g. memory search) MUST use fire-and-forget or background tokio tasks. (`crates/rsi/src/poll_controller.rs:7-18`, CLAUDE.md "Event Loop")
- `ui/height.rs` pre-computes line heights for virtual scrolling; rendering large sessions (1000+ events) depends on this cache. Invalidate only on event changes — re-computing on every render frame is the documented anti-pattern. (`crates/rsi/src/ui/height.rs`, CLAUDE.md "Content Rendering")
- `RenderCacheKey` and `CachedRenderedEvent` (in `types.rs`) are the cache contract for parsed event content; the cache is keyed on event id + render width. Changing the key tuple silently invalidates the cache for all rendered sessions. (`crates/rsi/src/types.rs:629-647`)
- `App.session_fold_states: HashMap<String, bool>` is keyed by UUID-as-string for serde compatibility — converting to `HashMap<Uuid, bool>` would break deserialization of older `state.json` files. (`crates/rsi/src/state.rs:99-100`)
- `DaemonClient` is single-threaded async — only one in-flight request at a time, fire-and-forget responses drain before the next request. Spawning a second request while a fire-and-forget is pending corrupts the response stream. (`crates/rsi/src/client.rs:80-140`)
- Crossterm event polling is non-blocking with a small timeout (~50ms typical). Increasing the timeout reduces input latency budget; reducing it spins the event loop. The current setting balances battery vs. responsiveness for a vim-native power user. (`crates/rsi/src/main.rs`, CLAUDE.md "Event Loop")
- `OverlayState` rendering runs on every frame regardless of activity; the inactive variants are zero-cost (no allocations) but the active variant's data MUST be cheap to clone for the render path. Avoid embedding `Vec<Session>` snapshots in overlays — store IDs and look up at render. (`crates/rsi/src/types.rs:1878`, see overlay rendering in `ui/overlay.rs`)
