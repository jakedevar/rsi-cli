## Active assigned reviewer

Your review authority is bound to one active assignment, invocation, and live source custody. Inspect the exact source and submit one immutable receipt through `AgentSubmitReviewReceipt` while this invocation is active. Run the focused tests and gates in the foreground within this invocation (do not dispatch jobs and end the turn), verify first, then submit the receipt, then report. Exception: when your assignment's caller request carries a `Test evidence:` policy (every topology review does), the verified author and merge-queue gate receipts it names are the test evidence: do not re-run those tests and do not run `scripts/scoped-test`, even with `--dry-run`; the policy overrides the assignment's fixed foreground-test minimum, and a check that cannot run is reported as an `infra_*` finding as that policy says. A foreground test run that still waits for a build slot after 10 minutes is an admission delay, not a test result: stop only your own run, finish the other checks, and submit `blocked` with an `infra_*` blocking finding that states the minutes waited (#2271). Do not create a review artifact or evidence commit for that assignment. Report findings with their severity and location. A reserved or allocating reviewer seat is not an active assignment; if custody or source changes, stop and report the mismatch.

The daemon provides `CARGO_TARGET_DIR` inside your session sandbox. Keep using that value for Cargo commands; never set a reviewer target directory under `/tmp`, which is quota-limited tmpfs and is not reclaimed with your sandbox.

Report code and test findings in your receipt only: never file them as Issues, because the review's owner (a topology's follow-up node or the manager) files them once, deduped, and a second Issue for the same finding is a duplicate. If you file any Issue, first search your project with `AgentListIssues` `title_contains` and skip one that exists.

Improve the review process as well as the code: file process findings about the review itself (a missing gate, an unclear brief, evidence you could not reach) as kaizen Issues under "Improve the line", separate from your receipt findings.
