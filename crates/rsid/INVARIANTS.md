# rsid Invariants

## Type contracts

- `SessionManager` owns three concurrent maps: `active: RwLock<HashMap<Uuid, TrackedSession>>`, `completed: RwLock<HashMap<Uuid, CompletedSession>>`, and `store: Mutex<Store>`. A session ID MUST appear in **at most one** of {active, completed} at any time; lifecycle handlers move (not copy) between them. (`crates/rsid/src/session/mod.rs:65-110`)
- `TrackedSession.session.status` is the source of truth for in-memory state; `Store` lags by the persistence channel depth. Readers MUST consult `active`/`completed` first, fall through to `Store` only on miss. (`crates/rsid/src/session/lifecycle.rs:62-196`)
- `SandboxAllocation { kind, root, branch, origin }` — `branch` is `Some(_)` iff `kind == GitWorktree`; `root` is canonicalized absolute path under `base_dir`; `origin` is the canonical `working_dir` (NOT persisted on the row, recoverable from `Session.working_dir`). (`crates/rsid/src/sandbox/mod.rs:48-58`)
- `StoreCommand` enum — every mutation type (`InsertSession`, `UpdateSessionStatus`, `InsertEvent`, `InsertTurnMetric`, `UpdateSessionMetadata`, `AttachProject`, `Shutdown`) flows through one mpsc channel with bounded capacity (`DEFAULT_QUEUE_CAPACITY = 256`). `Shutdown` is terminal; subsequent commands are dropped. (`crates/rsid/src/store_worker.rs:11-34`)
- `DaemonError` variants — `ChannelClosed` indicates store-worker channel disconnection; `InvalidParam` is the canonical RPC-rejectable error (used by path safety, sandbox refusal, and container-kind spawn gate). (`crates/rsid/src/error.rs:1-46`)
- `LATEST_SCHEMA_VERSION = 40` is the asserted-against constant, but the migration block in `init_schema` runs through V41 (`approval_wait_ms`). The constant lags the actual highest migration; tests asserting `LATEST_SCHEMA_VERSION` will not catch a row that requires V41. (`crates/rsid/src/store/mod.rs:40,757-764`)
- `DaemonEvent` variant payloads must serialize via `serde(tag = "type", content = "data")`. The `From<DaemonEvent> for BusEvent` impl enumerates every variant; adding a new variant without updating the converter compiles but emits an empty `event_type` at runtime. (`crates/rsid/src/bus.rs:14-184`)
- `ToolRegistry` is constructed once at `SessionManager::new` and wrapped in `Arc<ToolRegistry>`; tools are immutable post-construction. Per-session dynamic tools attach via `dynamicTools` in `thread/start`, not by mutating the registry. (`crates/rsid/src/session/mod.rs:162-164,103`)
- Workspace roots (`workspace_roots: Vec<PathBuf>`) are pre-canonicalized at startup. Empty slice = permissive (no containment check). Each entry must be a directory that exists. (`crates/rsid/src/session/mod.rs:96-98,212-234`)

## Lifecycle invariants

- `SessionStatus` write order in `finalize_session`: priority is `Interrupted > WaitingApproval > Failed > Completed`. Zero meaningful output OR non-zero exit code force `Failed`. (`crates/rsid/src/session/lifecycle.rs:103-127`)
- Sandbox allocation runs **BEFORE** Session insertion (`launch.rs:54-78`). Failure aborts the launch; the row is never persisted. Fail-closed: a sandbox-requested session that cannot allocate produces an RPC error, never silently runs without isolation. (`crates/rsid/src/session/launch.rs:51-78`)
- Sandbox cleanup transitions: insert with `SandboxCleanupState::Live` at launch (`launch.rs:469-471`), `Live → Purged` on `maybe_destroy_sandbox` success, `Live → Failed` on partial destroy. Orphan sweep on daemon restart re-attempts `Failed` rows and any UUID dirs without a matching live session. (`crates/rsid/src/session/launch.rs:1060-1199`, `crates/rsid/src/sandbox/mod.rs:11-31`)
- Rotation depth is gated at depth 4 — `rotation.rs:705-727` aborts the cascade with a system event when `child_depth >= 4`. Children inherit `parent.rotation_depth + 1`; original sessions start at 0. (`crates/rsid/src/session/rotation.rs:700-728,804`)
- `WaitingApproval` time accounting: `approval_wait_start: Option<Instant>` in `TrackedSession` is set when the session enters `WaitingApproval`; cleared into `approval_wait_total_ms` on resume or finalize. `saturating_add` defends against u64 overflow. The accumulator resets to 0 across rotation/retry boundaries. (`crates/rsid/src/session/lifecycle.rs:131-141,389-394`)
- `continue_session` requires the session to be in `Completed | Interrupted | Failed`; if active, it triggers `interrupt_session` then waits up to 10s on the event bus for the terminal transition before continuing. (`crates/rsid/src/session/lifecycle.rs:402-477`)
- `StoreWorker::run` loops on `rx.recv()`; receiving `Shutdown` triggers `drain_remaining()` then exits. Channel close = exit. Each command processed sequentially — no concurrent SQLite writes. (`crates/rsid/src/store_worker.rs:86-105,191-206`)
- Migration sequence in `Store::init_schema` is monotonic: every `if version < N` block ends with `PRAGMA user_version = N`. Reordering or skipping a block corrupts the schema. (`crates/rsid/src/store/mod.rs:62-766`)
- `ensure_base()` for sandboxes is called at daemon startup AND on every `allocate()`; idempotent and race-safe (`create_dir_all` + `chmod 0o700`). Chmod failure logs but does NOT abort. (`crates/rsid/src/sandbox/mod.rs:84-107,122`)

## Cross-crate contracts

- `rsid` emits the exact `SessionStatus` variant strings (`Starting`, `Running`, `WaitingApproval`, `Completed`, `Failed`, `Interrupted`, `Archived`, `Deleted`); the TUI matches them with `==`. Renaming a variant on either side breaks render. (`crates/rsi-common/src/types.rs:440-449`)
- `BusEvent.event_type` strings emitted by the `From<DaemonEvent>` impl are part of the wire contract — `rsi/src/notification_stream.rs` and any subscribed TUI code matches on these literals. (`crates/rsid/src/bus.rs:186-310`)
- `LaunchSessionParams.working_dir` is canonicalized at the RPC boundary (`rpc.rs:692-696`) BEFORE `launch_session` runs. Direct callers (rotation, retry) MUST canonicalize themselves; `launch.rs:46-49` performs defense-in-depth. (`crates/rsid/src/rpc.rs:684-733`, `crates/rsid/src/session/launch.rs:45-49`)
- `DaemonCapabilities::sandbox` defaults to `true` in `Default::default()`; daemon overrides to `false` if `sandbox_base` setup fails. TUI MUST consult `poll_controller.sandbox_supported` before showing the sandbox toggle. (`crates/rsi-common/src/rpc.rs:298-302,304-326`)
- `Session.workflow_id` is set on launch by `rsid` (research creates a workflow; plan / implement inherit and advance the stage). The TUI never writes `workflow_id` itself — it reads it through `ListSessions`. (`crates/rsid/src/session/launch.rs:543-602`)
- Raw SQL against `~/.rsi/rsi.db` is permitted (the daemon's `Store` methods are the preferred path because they auto-enforce invariants, but they are not the only path). Two hard rules apply project-wide and are documented in CLAUDE.md "Database Rules": (a) **no schema changes without a migration** in `crates/rsid/src/store/migrations/` with a `user_version` bump; (b) **no hard deletes (`DELETE FROM ...`) without explicit user consent** — default to logical delete. When writing raw mutations, respect daemon-enforced invariants: RFC 3339 nanosecond timestamps, canonical lowercase UUIDs, exact enum strings for status / kind / cleanup_state, and atomic sandbox tombstones (cleanup_state + null root + null branch in one UPDATE). (`crates/rsid/src/store/mod.rs`)

## Performance invariants

- `StoreHandle::try_send` returns `ChannelClosed` rather than blocking on a full channel; the worker logs `queue full, dropping command`. The store worker MUST keep up with daemon-side event production rate; the WARN_THRESHOLD_PCT = 80% backpressure trigger is observable via `tracing::warn!`. (`crates/rsid/src/store_worker.rs:11-13,107-128,269-283`)
- Slow-command threshold is 100ms (`SLOW_COMMAND_THRESHOLD_MS`) — any single store command exceeding this logs a warning. Sustained slow commands indicate either a missing index or a pathologically large `events` insert. (`crates/rsid/src/store_worker.rs:13,140-145`)
- WAL mode is enabled at `Store::open` (`PRAGMA journal_mode=WAL`) — concurrent readers must not block writers, and a single writer holds a SQLite-level lock. Disabling WAL would serialize all reads behind writes. (`crates/rsid/src/store/mod.rs:52-53`)
- `find_project_for_path` is documented O(n) on a sorted Vec — "microseconds, safe for hot path" — at expected scales of <100 projects. Past several hundred, switch to a trie. (`crates/rsid/src/session/launch.rs:97-98`)
- `events_to_openai_messages` allocates a fresh Vec on every continue / API resume; large rotation chains can balloon the conversation history. The function does not deduplicate or truncate — caller must enforce a turn cap if needed. (`crates/rsid/src/session/lifecycle.rs:36-60`)
- `ProjectIndex` is held under `RwLock`; mostly read on the hot path. Writes (CRUD via RPC) take the write lock briefly. Avoid holding the read lock across `.await` to prevent priority inversion. (`crates/rsid/src/session/mod.rs:77,131-133`)
- `EventBus` uses `tokio::sync::broadcast` with a fixed channel capacity (default 1024). Slow subscribers see `RecvError::Lagged` rather than memory growth — TUI must reconnect/poll on lag. (`crates/rsid/src/bus.rs:5-7`)
- `SandboxAllocator::list_on_disk` walks `base_dir` once per orphan sweep — O(n) in sandbox count. Acceptable at hundreds; persistent index needed past low thousands. (`crates/rsid/src/sandbox/mod.rs:165-185`)
