## Margin comments (teacher annotations)
- **L7** — *"resuming work from a handoff document through an interactive process"* — Same interactive-vs-autonomous trap that `create_plan.md` fell into. L33 and L45 then mandate "**immediately begin work** on the first action item — do NOT ask for confirmation or permission to proceed." The file is autonomous; delete "interactive" here. A reader taking L7 at face value will stall at every decision point.
- **L9–22** — *"CRITICAL — Original Question Passthrough (NON-NEGOTIABLE)"* — The mechanism is fine; its placement is not. This is scope creep exactly like `implement_plan.md` L116–131 — pipeline plumbing duplicated in every terminal command. Extract to a shared include (e.g. `_shared/bookend.md`) and reference by path. Principle #14 violated.
- **L11** — *"it takes priority over everything else"* — No. The priority declared here outranks even the handoff's own `## Immediate Next Action` field (see `create_handoff.md` L66–67). If a bookend is missing, the response is FAILED even if the next-action was executed perfectly. That is a ranking error: the bookend is metadata; the next-action is the work. Invert the priority or drop "over everything else."
- **L19** — *"**Original Research Question:** {1-2 sentence summary of the original question that started this pipeline}"* — "Research question" is the wrong noun here. The pipeline that fed this handoff may have started at `/create_plan` or `/master_implement`, not `/research_codebase`. The label is a leftover from the research-first pipeline. Use "Original Request" to match the handoff's own `## Original Request` section (`create_handoff.md` L63–65) and stop confusing the agent about which field to extract.
- **L28–45** — *Parameter-handling branches* — Branches 1 (path provided) and 2 (ticket number) duplicate ~80% of their bullets. DRY violation. Fold into a single branch: "(a) resolve the handoff path from the parameter (path or ticket); (b) execute the common handoff-intake flow." The ticket-resolution logic is the only real divergence and is 4 lines.
- **L30** — *"Immediately read the handoff document FULLY"* — Post-refactor antipattern. `FULLY` was grepped out of every other RPI command in Phase 1; this file was missed. Handoffs can be 300+ lines with embedded plan references. Replace with: "Read the handoff document via Grep-then-Read targeted on the fields the `<handoff_contract>` below extracts. Full-file reads only if the handoff is <400 lines."
- **L31** — *"Immediately read any research or plan documents that it links to under `thoughts/shared/plans` or `thoughts/shared/research`. do NOT use a sub-agent to read these critical files."* — This is the compounding-bloat move. Handoffs routinely reference 2–5 artifacts that are themselves 500–2000 lines. Reading all of them into the resuming agent's main context before a single action is the `master_implement`-pre-refactor pattern in miniature. Violates #5 (disk-is-the-channel) and #6 (discard-after-extract). The correct pattern: extract `{handoff_path, immediate_next_action, critical_refs[]}` into a small working set, then re-read *from disk* only the refs needed for the current todo.
- **L42–44** — *Second branch, same sins as L30–31* — Literal duplication. Same fix, one place.
- **L65** — *"Use the Read tool WITHOUT limit/offset parameters"* — Third `FULLY`-class directive. Delete. The shared `worker_preamble.md` already declares the targeted-range read budget; reference it.
- **L74–86** — *"Spawn focused research tasks"* — A Task-spawn template with no `<return_schema>`, no token cap, no forbidden-content list. The spawned sub-agent will return prose ("Summary of artifact contents and key decisions"), which the resuming agent then holds in context on top of the already-inlined handoff. Replace with a typed schema: `{artifact_path, status: present|missing|changed, drift_summary: ≤20 words, critical_refs_confirmed: list[file:line, ≤5]}`.
- **L84** — *"Use tools: Read"* — Read is fine, but the real tool the sub-agent needs is Grep — to locate drift in "Recent changes" without pulling whole files. Naming only Read anchors the sub-agent into the same full-file-read antipattern.
- **L85** — *"Return: Summary of artifact contents and key decisions"* — Unbounded prose return. Principle #3 (numeric caps) and #7 (forbidden-content) both violated. The sub-agent will return a page. Cap it.
- **L90–93** — *"Read critical files identified… Read files from 'Learnings' section completely… Read files from 'Recent changes'"* — Three more full-file-read mandates, fanning out from a single handoff. For a handoff with 6 "Recent changes" file refs and 4 "Learnings" refs, this is 10 file reads before Step 2 even starts. Replace with: "Read only the `file:line` ranges cited; if a ref lacks a line range, Grep for the change keyword first, then Read the surrounding ±40 lines."
- **L98–127** — *The analysis template* — Concrete format anchoring is good. No caps on any field. "Key Learnings Validated" can be 3 bullets or 30. "Next Actions To Take" is numbered but uncapped. Add `≤5 learnings, ≤10 actions, ≤140 chars per bullet`.
- **L129** — *"the ONLY exception is if you are genuinely confused about which of multiple conflicting paths to take — in that case, notify the user and respond with <docregblock>?</docregblock>"* — This is the only escape hatch in the file and it's load-bearing. `<docregblock>?</docregblock>` is an RSI-internal protocol signal that is documented nowhere in this command. Either explain what it does (the daemon detects it and prompts Jake), or use the same `<blocking_question>` schema the rest of the harness is converging on. Currently the agent has to know folklore to emit it.
- **L133–145** — *Step 3: Create Action Plan* — Good use of TodoWrite, but no cap on todo count. A handoff with 12 "Action Items & Next Steps" will generate 12 todos plus "any new tasks discovered during analysis" — unbounded. Cap at 8; anything over 8 becomes a sub-plan.

- **L154–184** — *"Guidelines"* — "Be Thorough / Be Decisive / Leverage Handoff Wisdom / Track Continuity / Validate Before Acting" is vibes. Collapse into `<constraints>` XML with concrete rules. - **L186–191** — *"Commit and Push — MANDATORY"* — Verbatim duplicate of `create_plan.md` L467–472, `research_codebase.md` L212–216, and `create_handoff.md` L118–124. Principle #14. Same reckless `git add` of the entire `thoughts/` directory with no forbidden-path list.

- **L199** — *"**Original Research Question:**"* — Same label-mismatch as L19. The handoff has `## Original Request`; this command wants to emit "Original Research Question". The agent has to translate between the two on every invocation. Align the labels.
- **L210–234** — *"Common Scenarios"* — Four scenarios (Clean / Diverged / Incomplete / Stale) described in 2–4 lines each with no decision logic. "Need to re-evaluate strategy" is not actionable. Either give the agent a concrete decision tree ("if `git log` shows >N commits since handoff timestamp → treat as stale → skip to §re-evaluate"), or delete the section. As written it's decoration.
- **L236–254** — *"Example Interaction Flow"* — Shows the agent reading, spawning, waiting, presenting, and starting — i.e. the exact over-eager full-context flow the file mandates. ## Overall verdict

This file is the RPI refactor's blind spot, and it is currently the single worst context discipline case in the project-local command set. Every other RPI command got `FULLY` grepped out in Phase 1; this one still has three hits. `master_implement.md` got a `<handoff_contract>` and `<discard_after_extract>` in Phase 2 to stop stage outputs from compounding across the pipeline; the resuming agent — the agent that *receives* the handoff — has neither, and the mechanism it uses to consume a handoff is exactly the inlining pattern Phase 2 tore out of the orchestrator. You fixed the upstream leak and left the downstream one wide open. A long handoff with three linked plan + research docs will saturate the resuming agent's context before Step 2's analysis synthesis even runs, and after that every subsequent action is paying a multi-thousand-token tax on every turn.

The second-order problem is the same DRY debt that plagued the sibling commands pre-refactor, except here it is more severe because the Original-Question-Passthrough block is declared **three separate times** in the same file (L9–22, L129 interjection, L193–206) — a maintenance surface guaranteed to drift. The commit-push block is cloned from four siblings. Parameter-handling branches 1 and 2 are 80% duplicated with each other. And there is zero reference to `_shared/worker_preamble.md` despite this command being the resumption partner of the RPI pipeline. The file has not had the refactor applied.

**Highest-ROI single improvement: add a `<handoff_contract>` extraction block + a `<discard_after_extract>` instruction, and replace L30/L31/L42/L43/L65/L91–93 with a disk-first read discipline.** Concretely: the resuming agent extracts `{handoff_path, immediate_next_action, ticket_id, critical_refs[]}` from the handoff via Grep-then-Read, writes those four fields into its working set, and then drops the handoff body. Linked plan/research docs are touched only when the current todo requires them, and then via ranged Read. That single pair of edits takes the file from D to B- in one pass, because it fixes context discipline, stop conditions, and the compounding-bloat pattern in one structural change. After that, three more mechanical passes — reference `_shared/worker_preamble.md`, collapse the bookend triplication into one shared include, and collapse the two parameter branches into one — and the file matches the post-refactor voice of `create_plan.md` and `master_implement.md`. The bones are workable; the discipline is missing.
